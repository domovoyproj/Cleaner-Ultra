# PhotoSort Space

Основная задача — объяснить использование места и дать пользователю управляемый путь очистки. Медиатека PhotoSort остаётся отдельным инструментом внутри приложения.

## Версия 0.6

- Реальные показатели томов; анализ выбранной папки или диска в фоновом потоке.
- Размеры всех обычных файлов, категории, индексированные списки папок, карта, поиск и пагинация.
- Поиск крупных файлов от 100 МБ и файлов TEMP старше 7 дней.
- Ручной выбор без предвыделения, просмотр всех выбранных путей, корзина рядом с исходным файлом и восстановление без перезаписи.
- Отдельный журнал переносов; после прерывания неоднозначные копии сохраняются. Изменение размера или времени файла проверяется перед переносом, содержимое — через SHA-256 во время файловой операции.
- Корзина открывается по 60 записей на страницу; старые переносы доступны независимо от общего числа сохранённых файлов.
- Защита служебных корзин, рабочих данных приложения, системных каталогов, загрузочных данных и файлов профиля Windows сохраняется при повышении прав.
- Перезапуск настольного приложения с правами администратора через UAC; анализ фрагментации и оптимизация через штатный `defrag /O`, без принудительного выбора HDD-операции для SSD.
- Открытие штатного хранилища Windows, удаления приложений и системной корзины.

Файлы в корзине PhotoSort занимают место на исходном диске. Интерфейс не выдаёт этот объём за освобождённый. Автоматического безвозвратного удаления нет. Для окончательной очистки системных данных используются инструменты Windows. Запуск оптимизации не выдаётся за её успешное завершение: состояние операции показывает сама Windows.

## Архитектура

`space.sqlite3` независима от прежней `library.sqlite3`. Сканирование записывает метаданные пачками по 512 файлов и агрегирует размеры предков в тех же транзакциях. Для открытия карты используется индекс непосредственного родителя, без загрузки дерева целиком. API списков возвращает до 60 файлов или 100 папок за запрос. Быстрый опрос прогресса не перечитывает категории и не декодирует медиа.

Пути и идентификаторы сканирования проверяются повторно перед переносом. Ссылки и подменённые родительские каталоги не принимаются. Новый запуск не продолжает устаревший список под видом полного анализа: частичные результаты помечены отдельно, повторный анализ строит новый снимок.

## Дальнейшее развитие

Карта в 0.6.1 включает непосредственные файлы и вложенные папки, поддерживает выбор, переходы, масштаб, перемещение и разворот. До 120 крупнейших элементов показаны отдельно; остальные объединены с сохранением полного объёма. Весь список доступен по 60 элементов. Индекс `(scan,parent,size,id)` не требует загружать дерево диска для открытия папки; прежние индексы обновляются пачками.

- Физически выделенный размер на NTFS, учёт жёстких ссылок и разреженных файлов без двойного подсчёта.
- Универсальные дубли любых файлов: сначала размер, затем частичный отпечаток и полная проверка SHA-256; порционный просмотр сохраняемых копий.
- Отдельные проверяемые правила кешей приложений с пояснением последствий, без очистки паролей, сессий и рабочих проектов.
- Перенос архивов на другой диск с проверкой и восстановлением, чтобы освобождать исходный том с сохранением копии.
- Собственный инвентарь установленных приложений и запуск их официальных деинсталляторов.
- Инкрементальный анализ с измерениями на больших дисках и учётом изменений файловой системы.
- Встроенное чтение результата системной оптимизации вместо отдельного окна.

Эти пункты не объявлены функциями версии 0.6. Чистка реестра и обещания «ускорения на N процентов» без измерений не входят в концепцию.
