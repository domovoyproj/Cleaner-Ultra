# Cleaner Ultra: безопасность данных

Очистка файлов переносит выбранное в корзину на том же диске с журналом и SHA-256. До окончательного удаления корзины свободное место не увеличивается. Восстановление не заменяет существующие файлы. Системные каталоги, рабочие базы и корзины исключаются из очистки.

Автозагрузка ограничена HKCU Run/RunOnce. Отдельная очистка реестра проверяет значения по умолчанию HKCU App Paths, COM InprocServer32/LocalServer32 и DisplayIcon непосредственных подразделов Uninstall; исправляет только однозначные ссылки на отсутствующие локальные файлы. Деревья, службы, драйверы и HKLM не удаляются. Перед удалением сохраняются точные байты и тип в SQLite с synchronous=FULL. Повторная проверка защищает от устаревшего списка. При конфликте восстановления другая запись сохраняется. Между проверкой и записью реестр может быть изменён другим процессом: Windows не предоставляет compare-and-swap для значения; резервная копия сохраняет исходное содержимое. Не запускайте параллельные редакторы автозагрузки во время восстановления.

Удаление приложений запускает зарегистрированный деинсталлятор. Cleaner Ultra не удаляет вручную службы, драйверы или каталоги приложений и не подменяет оценку установщика измеренным освобождением места.

Оптимизатор использует FSCTL API ядра Windows, блокирует запись и удаление обрабатываемого файла, сверяет содержимое и число фрагментов. SSD, неизвестные носители, неподдерживаемые файловые системы, системные, зашифрованные, сжатые и разреженные файлы не перемещаются. Перенос проверен на специально фрагментированном собственном NTFS-файле с проверкой SHA-256. На механическом HDD отдельное испытание не проводилось.

Сервер слушает loopback, проверяет Host и токен на изменение состояния. Не публикуйте его порт наружу. JSON-отчёты содержат локальные пути. Хранилище и резервные копии остаются на компьютере.

TRIM использует MSFT_Volume.Optimize/ReTrim через COM/WMI внутри приложения: только Windows выбирает свободные диапазоны. Самостоятельные raw DSM-операции по карте живого тома не выполняются. После начала ReTrim отмена не поддерживается. Профиль WebView2 находится внутри данных приложения и исключается из дистрибутива.

Мастер применяет только отредактированный и подтверждённый список. До этого операции чтения не изменяют файлы/реестр. Сервер принимает выданные сканированием идентификаторы, перепроверяет значения, пути и поколение файлового снимка; раздельные снимки реестра и автозагрузки не подменяют друг друга. Между шагами возможен частичный результат: ошибки показываются отдельно и не считаются успехом. Удаление кеша затрагивает только принадлежащие приложению имена превью, оригиналы не удаляются.

Монитор процессов только читает CPU, память и имена доступных процессов. Смена питания использует существующие схемы Windows через PowrProf, требует подтверждения и сохраняет предыдущую схему в журнал до вызова PowerSetActiveScheme. При невозможности сохранить журнал схема не меняется. Очистка не завершает процессы и не применяет скрытых настроек служб/защиты.
