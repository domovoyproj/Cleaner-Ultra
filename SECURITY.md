# Cleaner Ultra: безопасность данных

Очистка файлов переносит выбранное в корзину на том же диске с журналом и SHA-256. До окончательного удаления корзины свободное место не увеличивается. Восстановление не заменяет существующие файлы. Системные каталоги, рабочие базы и корзины исключаются из очистки.

Изменение реестра ограничено значениями HKCU Run/RunOnce. Перед удалением сохраняются точные байты и тип в SQLite с synchronous=FULL. Повторная проверка защищает от устаревшего списка. При конфликте восстановления другая запись сохраняется. Между проверкой и записью реестр может быть изменён другим процессом: Windows не предоставляет compare-and-swap для значения; резервная копия сохраняет исходное содержимое. Не запускайте параллельные редакторы автозагрузки во время восстановления.

Удаление приложений запускает зарегистрированный деинсталлятор. Cleaner Ultra не удаляет вручную службы, драйверы или каталоги приложений и не подменяет оценку установщика измеренным освобождением места.

Оптимизатор использует FSCTL API ядра Windows, блокирует запись и удаление обрабатываемого файла, сверяет содержимое и число фрагментов. SSD, неизвестные носители, неподдерживаемые файловые системы, системные, зашифрованные, сжатые и разреженные файлы не перемещаются. Перенос проверен на специально фрагментированном собственном NTFS-файле с проверкой SHA-256. На механическом HDD отдельное испытание не проводилось.

Сервер слушает loopback, проверяет Host и токен на изменение состояния. Не публикуйте его порт наружу. JSON-отчёты содержат локальные пути. Хранилище и резервные копии остаются на компьютере.

TRIM использует MSFT_Volume.Optimize/ReTrim через COM/WMI внутри приложения: только Windows выбирает свободные диапазоны. Самостоятельные raw DSM-операции по карте живого тома не выполняются. После начала ReTrim отмена не поддерживается. Профиль WebView2 находится внутри данных приложения и исключается из дистрибутива.
